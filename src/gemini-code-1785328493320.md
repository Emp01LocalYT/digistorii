Implement the Purchase Return / RTV (Return to Vendor) feature based on the following requirements and workflow:

### Feature Scope: Purchase Return / RTV

1. Selection & Context:
   - Allow the user to select a Supplier and/or an existing GRN.(searchable with grn number,supplier name,date)
   - Load the products and their received quantities from the selected GRN.
   - Handled Case: For partial GRNs, strictly allow returns only against quantities that were actually received in that GRN.

2. User Input & Validation:
   - The user selects specific product/variants and inputs the desired return quantity.
   - Validation Rule: Strictly prevent returning more than `(GRN Received Quantity - Previously Returned Quantity)`. 

3. Inventory & Data Integrity:
   - Link the purchase return record directly to the original GRN (and its associated PO).
   - DO NOT alter or modify the original GRN quantities or records.
   - Update stock balance by recording transactions in the existing Stock Ledger mechanism:
     - txn_type = 'Purchase Return'
     - qty_in = 0
     - qty_out = <returned_quantity>

4. Implementation Guidelines:
   - Maintain the same architectural pattern and code structure used previously for 'Sales Return' and 'Stock Adjustment'.
   - Ensure proper transaction handling (DB transactions/rollback) when creating the purchase return record and inserting into the Stock Ledger.

Please generate the necessary backend logic, database schema/migration updates (if required), and frontend workflow components to support this flow.
