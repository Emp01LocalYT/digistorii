# Specification & Prompt: Refactor Stock Adjustment Form to Multi-Item Document Table

## Overview
Refactor the **Stock Adjustment Page** (`page.tsx`) to support multi-item line entry. The current form only allows adjusting one product variant at a time. It needs to support adjusting multiple variants under a single adjustment document (e.g., auditing a batch of damaged clothing) using a dynamic line-item table.

---

## 1. Requirements & Core Changes

### A. Product Lookup & Browsing
1. **Existing Inline Search:** Retain the fast-search input for scanning barcodes or typing Name/SKU directly into the form. When a item is selected via search/barcode, append it to the line-items table.
2. **Product Lookup Modal:** Add a **"Browse Products"** button adjacent to the search input. 
   - Integrate the existing shared `ProductLookupModal` component used across other pages in the app.
   - Enable multi-selection in the lookup modal so users can check off multiple variants at once and import them into the document table.

### B. Header Level Fields
- **Transaction Date** (`txn_date`)
- **Warehouse** (`warehouse_id`)
- **Locator** (`locator_id`)
- **Header Reason / Remarks** (`reason`) - Acts as a default reason for all rows 

### C. Convert "Stock Count & Calculation" Card to Line-Item Table
Replace the current single-product card with a dynamic **Line Items Table**.

Each row must contain:
1. **Product Details:** Name, SKU, Color/Variant, and Barcode.
2. **System Qty:** Automatically fetched for that specific `variant_id` based on the selected `warehouse_id` and `locator_id`. Show a loading spinner while fetching.
3. **Physical Count Qty:** Editable `number` input field.
4. **Calculated Variance:** Dynamic calculation: `Physical Qty - System Qty`.
   - Show `+X (Stock Gain)` in green if `Physical Qty > System Qty`.
   - Show `-X (Stock Loss)` in red if `Physical Qty < System Qty`.
   - Show `0 (No Change)` if equal.
5. **Action:** A remove button (trash icon) to delete the row from the table.

## 2. Updated State & Payload Structure

### Form & Line Item Types
```typescript
type StockAdjustmentLineItem = {
  variant_id: number;
  sku: string;
  name: string;
  color?: string | null;
  barcode?: string | null;
  system_qty: number | null;
  physical_qty: string;
  reason?: string;
  loading_stock?: boolean;
};

type StockAdjustmentForm = {
  txn_date: string;
  warehouse_id: string;
  locator_id: string;
  reason: string;
  items: StockAdjustmentLineItem[];
};
```
### API Payload Structure
Ensure the submit handler constructs and posts the batch payload to /api/stock-adjustments:
```typescript
JSON
{
  "txn_date": "2026-08-05",
  "warehouse_id": 1,
  "locator_id": 3,
  "reason": "Audit variance",
  "items": [
    {
      "product_id": 101,
      "physical_qty": 5,
      "reason": "Damaged goods"
    },
    {
      "product_id": 102,
      "physical_qty": 12,
      "reason": "Audit variance"
    }
  ]
}
```

## 3. Validation Rules
Warehouse & Locator: Must be selected before adding products or submitting.

Duplicate Prevention: If a product variant is already present in the line items table, prevent duplicate row creation and show a notification or automatically highlight/focus the existing row.

Line Items Validation:

Table cannot be empty upon submission.

Every row must have a valid non-negative physical_qty.

Zero-variance items (Physical Qty == System Qty) should trigger a confirmation warning or be blocked depending on validation rules.
