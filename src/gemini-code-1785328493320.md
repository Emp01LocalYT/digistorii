# Refactoring User Quota & Adding Razorpay "Buy More Users" Workflow

## Context & Requirements
We need to update our user limit checking logic and build an end-to-end "Buy More Users" feature. 

### Core Logic Changes:
1. **Quota Source:** The source of truth for a company's maximum allowed users is `company_subscriptions.max_users`. 
   - `company_subscriptions.max_users` is initialized based on the plan limit during subscription creation.
   - When checking user limits, we should evaluate `company_subscriptions.max_users` directly (or fallback to the plan limit if `max_users` is `NULL`).
2. **Add Seats Workflow:**
   - Base Price: ₹100 per additional user seat.
   - Flow: In the Admin UI, the user specifies how many extra seats they want to buy (e.g., `2`), clicks "Pay & Continue", which calculates the total amount (e.g., `2 * ₹100 = ₹200`), and triggers Razorpay Checkout.
   - Post-Payment Success: On payment confirmation (webhook or verified callback), increment the existing `company_subscriptions.max_users` by the purchased amount (e.g., existing `5 + 2 = 7`).

### Task 2: "Buy More Seats" Modal & Dynamic Pricing Workflow

Add a dedicated payment workflow modal for purchasing additional user seats.

#### Component Requirements:
1. **Quantity Selector Modal:**
   - Add a state-driven modal triggered by clicking "Buy More" on the Total Users metric card or from the limit error toast.
   - Include an interactive number input or stepper (`-` / `+` buttons) to select `additionalSeats` (default: `1`, min: `1`).
   - Dynamic Cost Breakdown:
     - `Price per seat:` **₹100**
     - `Additional seats:` **{additionalSeats}**
     - `Current capacity:` **{maxUsers} seats** → `New capacity:` **{maxUsers + additionalSeats} seats**
     - `Total payable amount:` **₹{additionalSeats * 100}**

2. **Checkout Execution ("Pay & Continue"):**
   - On clicking **"Pay & Continue"**, call `POST /api/admin/billing/buy-seats` passing `{ seatCount: additionalSeats }`.
   - Use the returned Razorpay `orderId` and calculated amount (`additionalSeats * 100 * 100` paise) to launch the Razorpay Checkout modal:
     ```typescript
     const options = {
       key: razorpayKey,
       amount: seatCount * 100 * 100, // Amount in paise (e.g., 2 seats = 20000 paise = ₹200)
       currency: "INR",
       name: "Purchase Extra User Seats",
       description: `Adding ${seatCount} user seat(s) to your organization`,
       order_id: orderId,
       handler: async (response: RazorpayPaymentResponse) => {
         // Post payment verification API call
         await verifyAndUpgradeSeats({
           razorpay_order_id: response.razorpay_order_id,
           razorpay_payment_id: response.razorpay_payment_id,
           razorpay_signature: response.razorpay_signature,
           seatCount: additionalSeats,
         });
       },
       theme: { color: "#2563EB" },
     };
     ```

3. **Database Seat Increment Logic:**
   - Upon payment verification, execute an atomic increment update on `company_subscriptions`:
     ```sql
     UPDATE public.company_subscriptions
     SET 
       max_users = COALESCE(max_users, 5) + $1,
       updated_at = NOW()
     WHERE company_id = (SELECT id FROM public.companies WHERE subdomain_url = $2)
     RETURNING max_users;
     ```
   - On success, return the updated `max_users` capacity, update the UI state dynamically, close the modal, and show a success notification (`Successfully added X seats! Your new limit is Y users.`).
